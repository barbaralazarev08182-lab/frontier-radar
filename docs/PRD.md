# Frontier Radar — 产品需求文档（PRD）

> 版本：0.1 · 阶段 0 草案 · 个人使用

## 1. 愿景

Frontier Radar 是一个**个人前沿信息雷达**，每天从可信数据源中自动发现近期值得关注的 AI / 机器学习 / 开源项目 / Vibe Coding / 产品设计 / 量化金融相关项目、论文、模型、数据集、Demo、工具与产品，并用 AI 把它们解释成**人能读懂、能立刻行动**的条目。

它不是新闻聚合器，不是热榜爬虫。它的核心价值是：**发现 → 解释 → 转化为我可以做的事**。

## 2. 目标用户

仅本人（单用户）。因此：

- 不需要多租户、注册登录流程（仅 Supabase 自身鉴权即可）。
- 不需要复杂的权限系统，但仍使用 Supabase RLS 做最低限度保护。
- 个人偏好（关注的领域、屏蔽词、权重）会直接影响评分。

## 3. 核心价值主张

对每一条入选内容，必须能回答以下 7 个问题（这是 AI 分析的结构化输出契约）：

1. **它是什么** —— 一句话定义。
2. **它解决了什么问题** —— 痛点与场景。
3. **真正的新东西是什么** —— 区别于已有方案的关键差异（不是营销话术）。
4. **为什么现在值得关注** —— 时机判断（增长拐点、生态成熟、互补技术出现等）。
5. **是否有代码或 Demo** —— 可用性信号。
6. **复现难度如何** —— easy / medium / hard / unknown，并给出判断依据。
7. **我可以基于它做什么** —— 1–N 条可执行的个人项目灵感。

## 4. 阶段 1 范围（MVP）

### 4.1 数据源（仅 3 个）

| 数据源 | 主要抓取对象 |
| --- | --- |
| GitHub REST API | 仓库（repo） |

### 4.2 页面（仅 4 个）

| 页面 | 作用 |
| --- | --- |
| **Today** | 今日雷达：按 Frontier Score 排序的当日入选条目，每条带 7 点解释摘要。 |
| **Explore** | 浏览全部历史条目：按来源 / 类型 / 标签 / 评分 / 时间筛选与搜索。 |
| **Saved** | 收藏夹：保存的条目 + 个人笔记 + 文件夹分组。 |
| **Idea Lab** | 灵感实验室：基于条目产生的个人/AI 灵感，关联到来源条目，可标注状态。 |

## 5. 非目标（阶段 1 不做）

- 不做用户社区、评论、分享。
- 不做实时推送通知（仅每日一次采集）。
- 不接入 GitHub 之外代码托管、不接入 Twitter / Reddit 等社交源。
- 不做全文翻译；AI 摘要用中文，但保留原文链接。
- 不做付费墙、不投放广告。
- 不引入 PRD 未列出的技术栈或第三方依赖。

## 6. 关键原则（开发红线）

1. **原始数据与 AI 分析结果分开存储**：`raw_items` 保存不可变原始 payload，`ai_analyses` 保存结构化分析结果，二者通过 `item_id` 关联。
2. **所有外部内容必须保留原始来源与链接**：每条 item 至少存 `source_id`、`source_url`、`external_url`。
3. **API Key 只能存在服务端环境变量**：仅 `NEXT_PUBLIC_SUPABASE_URL` 与 `NEXT_PUBLIC_SUPABASE_ANON_KEY` 可暴露给前端，其余一律服务端。
4. **所有采集器必须支持错误处理、重试、缓存、Rate Limit**：通过 `collection_runs` 表记录每次运行状态与剩余配额。
5. **所有 AI 输出必须使用结构化 JSON**：定义 `ItemAnalysisResult` 契约，模型输出必须可解析为该结构。
6. **不允许只依赖总 Star 数判断热度**：评分包含动量（增长）维度，总 Star 仅作为基础信号。
7. **必须保存每日指标快照**：`item_metrics_snapshot` 按日记录，用于计算 24h 与 7d 增长。
8. **不要一次性开发整个网站**：按 `docs/PHASES.md` 分阶段推进，每阶段独立验收。
9. **不要擅自增加新的技术栈或依赖**：新增依赖需经用户确认。
10. **每完成一个阶段，先运行类型检查、构建和基础测试**：未通过不进入下一阶段。

## 7. 成功标准（阶段 1）

- 每日自动采集 3 个数据源，并在 `collection_runs` 留下成功/部分成功记录。
- 每日生成指标快照，能正确计算 24h / 7d 增长。
- 每条入选条目带结构化 AI 分析（7 点解释）。
- 4 个页面可访问、可筛选、可搜索。
- `tsc --noEmit`、`next build`、基础测试全部通过。
- 部署到 Vercel，Supabase 作为数据库。
